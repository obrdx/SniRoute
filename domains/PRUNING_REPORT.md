## 剪枝原则

1. **suffix 不是另一批 SNI**：原始 37,300 条 `is_suffix=1` 的同名记录不再复制到探测池。运行时只使用具体 hostname；是否匹配分流规则不能仅根据 suffix 直接推导。
2. **跨分类全局去重**：每个具体 hostname 仅归属一个主分类。`cross-category-reference.csv` 保留其他原始分类信息。
3. **保留代表性端点**：同一服务优先保留网站入口、API、认证、媒体/CDN、下载等不同用途的少量域名，而不是其所有市场别名、广告遥测、长尾边缘节点。
4. **排除不适用协议的大批量条目**：NTP、STUN 和部分 DDNS/Tracker 列表不默认充当 443/TLS 探测样本；不代表这些服务或域名无效。
5. **网址并不等于有效的 SNI 探测目标**：不能从后缀规则推断该主域存在 443/TLS 服务。本次仅基于清单内容和结构优化，未进行在线 DNS 或连接有效性验证。
6. **限制型站点适量保留**：避免大量不稳定镜像/随机站点主导阻断结论；保留类别覆盖的代表性域名及人工复核列表。
7. **不合并 API 与网站入口**：当同一服务的主站、API、CDN 对分流有独立价值时保留不同子域名。

## 使用说明

- `quick-test.txt`：首次检查一条线路的快速 SNI 列表。
- `full-test.txt`：完整精简域名列表（每行一个具体 hostname）。
- `domains.csv` / `quick.csv`：沿用原 CSV 的九列结构；全部 `is_suffix=0`，每个 hostname 仅出现一次。
- `categories/`：保留原始 00–18、20 分类的 TXT 格式，便于 TUI 选择测试分类。
- `cross-category-reference.csv`：合并时保留的原始多分类关系。
- `excluded-for-review.csv`：未选入的域名，仅记录原始来源和剪枝原因，可按需恢复。

## 结果解释和重要限制

- **基线最好使用你自己控制、能正常进行 TLS 的独立域名及观测端**。清单中的网络检测和 IP 回显站只用于辅助对照，不应直接认定为“中性不分流基线”。
- 受控探测出口 IP 与真实网站访问出口 IP 必须分别记录。
- 失败、超时、403 等不能自动认定为服务商封锁；需结合观测端回执与参考网络测试。
- 本次没有验证域名 DNS 是否仍存在、443 是否可连接、证书是否有效，也没有检查是否被服务商实时阻断。
- 因为未实时校验，某些长尾条目的优先级判定是启发式的；如有专门研究对象，请从排除清单中恢复，或加入 `20-custom.txt`。
